        一旦抛未捕获异常，StreamingResponse 会中途掐断 chunked 流且不发结束帧
        → 浏览器 ERR_INCOMPLETE_CHUNKED_ENCODING → 前端 fetch 抛 TypeError:
        network error（前端 sawTerminal 兜底只处理干净 EOF，救不了 chunked 崩断）。
        而会话在导入前就已 createSession，每次崩断留一个空壳，刷新后 activeSessionId
        重置为 null，重试再建 → 攒成一堆。DB 实证：文档 AVfuw… 的 session 48 成功
        （42 用例/8 消息），其后 49~55 全是 0 用例 0 消息的空孤儿。
  ├─ 根治（后端）：events() 拆成 _events_inner() + 外层 events() 包裹，捕获所有
  │   未预期异常 → 统一转成 assistant_message + error + done 帧，流干净收尾，前端
  │   拿到可读中文原因并复位（backend/app/api/routes_upload.py，PRD/脑图两端点共用）。
  ├─ 新增 DELETE /api/sessions/{id}：手动按序级联删 Feedback→TestCase→Message→
  │   ClarificationState→Session（init_db 建表未走迁移，不依赖 DB 层 CASCADE）。
  │   前端 SessionList 每行加垃圾桶按钮（hover 显示 + 二次确认），client.ts 加
  │   deleteSession，ChatPage 加 handleDeleteSession（删前先 abort 在跑任务、删后
  │   切到剩余首个会话或 null）。用于清掉现有孤儿会话。
  └─ 前端孤儿防护：handleLarkImport 记录 createdNewSid + gotContent，若「本次为
      导入新建的会话 + 全程没收到任何内容 + 无后续脑图阶段」则在 onError 里直接删掉
      这个空会话，不再插错误气泡，避免重试堆积（frontend/src/pages/ChatPage.tsx）。

■ 2026-07-01 — 修复飞书链接导入过一会儿界面内容消失
  背景：飞书导入进度出现后聊天区变空白，Console 报
        net::ERR_INCOMPLETE_CHUNKED_ENCODING 200 + TypeError: network error。
        根因是 make dev-backend 的 uvicorn --reload 在长导入（lark-cli 抓取 +
        LLM 澄清/知识抽取）过程中被 backend/ 下文件变动触发热重载、掐断 SSE 流。
  ├─ 根治：Makefile dev-backend 加 --reload-dir app --reload-include '*.py'，
  │   只在 app/ 下 .py 变动时重载，非代码写入不再打断流式请求。
  ├─ 前端可见提示：handleLarkImport 的 PRD/脑图两处 onError 改为在清进度的同时
  │   插入一条 assistant 错误气泡（❌ 飞书导入中断…请重试），不再静默变空白
  │   （frontend/src/pages/ChatPage.tsx）。
  └─ 前端中断兜底：streamUpload/streamLarkImport/streamMindmapUpload 加
      sawTerminal 标记，SSE 因 EOF 结束却从未收到 done/error 帧时主动 onError，
      避免"既不 done 也不 error"的僵状态（frontend/src/api/client.ts）。

■ 2026-07-01 — 「停止任务」真正中断所有任务（前端 + 后端）
  背景：点右下角「停止任务」时任务一直「正在执行」无反应；用户要求停止 =
        真正中断请求与后端 LLM 调用，而非仅前端解锁 UI。
  ├─ 前端 handleStopRequest/handleStopConfirm：不再要求必须注册过 cancel fn，
  │   有 runningTaskLabel 即弹确认框；cancel fn 可选，无则只走兜底清 UI 状态。
  ├─ 知识库预览（此前卡死那条）：fetchKnowledgePreview 新增可选 AbortSignal；
  │   startKnowledgePreview 与会话恢复 hydrate 路径均注册 AbortController，
  │   「停止」可真正取消该 GET 请求（frontend/src/api/client.ts、pages/ChatPage.tsx）。
  └─ 非流式 /api/generate：generate() 增参 raw_request: Request，把
      generate_test_cases 包成 asyncio 任务与「断连轮询」竞速，客户端断开即
      llm_task.cancel() → 取消底层 httpx → 真正停到大模型，且不落库、返回 499
      （backend/app/api/routes_generate.py）。
  说明：chat / upload / lark / mindmap / clarify / generate(流式) 本就通过 SSE
        AbortController + Starlette 断连取消能真正停止，无需改动。

当前可用接口速查
================================================================================
  — 鉴权 / 项目 —
  POST   /api/auth/register         注册
  POST   /api/auth/login            登录（返回 JWT access_token）
  GET    /api/auth/me               当前用户
  GET    /api/projects              项目列表
  POST   /api/projects              新建项目
  DELETE /api/projects/{id}         删除项目

  — 会话 / 对话 —
  POST   /api/chat                  流式对话（SSE）
  GET    /api/sessions              会话列表
  POST   /api/sessions              新建会话
  PATCH  /api/sessions/{id}         会话重命名
  GET    /api/sessions/{id}/messages 会话消息历史
  GET    /api/sessions/{id}/clarification_state 会话澄清状态（刷新回放）

  — 上传 / 澄清 / 生成 —
  POST   /api/upload                上传文档（返回解析结果 + 澄清问题）
  POST   /api/upload/stream         上传 PRD（SSE：解析 / 知识预览 / 自动分类）
  POST   /api/upload/mindmap/stream 上传测试脑图（SSE，Markdown outline）
  POST   /api/upload/lark/stream    飞书文档导入（SSE，调用 lark-cli）
  POST   /api/clarify/initial/stream 首轮澄清（SSE，PRD/脑图至少一份）
  POST   /api/clarify/followup/stream 续答澄清（SSE）
  POST   /api/generate              生成测试用例（PRD + 脑图双输入）
  POST   /api/mindmap/generate      从 PRD 生成测试脑图并存入飞书文档（返回飞书链接）

  — 用例 / 导出 —
  GET    /api/cases                 用例列表（跨会话浏览）
  GET    /api/sessions/{id}/cases   指定会话用例
  DELETE /api/cases/{id}            删除用例
  POST   /api/export/cases          按勾选的用例 ID 导出 Excel
  GET    /api/export/{session_id}   导出会话全部用例 Excel

  — 反馈 —
  POST   /api/feedback              提交反馈（like / dislike / edit；edit 异步触发 diff 分析；dislike 可带 reason 进分诊）
  GET    /api/feedback/recent       最近 N 条已分析的 edit 反馈（intent + summary）
  GET    /api/feedback/negative     负反馈归纳记录（edit+dislike，含规则全文 + 消费出口；「负反馈」页数据源）
  GET    /api/feedback/evolution/summary  反馈进化总览（三出口 待消费/已消费 计数 + intent 分布）

  — 模块 / 知识库 —
  GET    /api/modules               模块列表（含 code 英文名）
  POST   /api/modules               新建模块（可带 code 英文名 = 用例编号前缀）
  PUT    /api/modules/{id}          改模块中文名 / 英文名 code / 描述
  DELETE /api/modules/{id}          删除模块（名下资产变未分类，不级联删）
  GET    /api/module_relations      模块关联关系列表
  POST   /api/module_relations      新建关联
  DELETE /api/module_relations/{id} 删除关联
  GET    /api/documents             文档列表（module_id / only_orphan / role 过滤）
  GET    /api/documents/{id}        文档详情（含截断正文，只读预览）
  PATCH  /api/documents/{id}        改文档归属模块（module_id=null 取消归属）
  GET    /api/knowledge/preview     知识预览
  GET    /api/knowledge/stats       知识库总览（总条目 / 类型 / 模块覆盖 / 近 N 天新增）
  GET    /api/knowledge             知识条目列表
  GET    /api/knowledge/{module_id} 指定模块知识条目
  PUT    /api/knowledge/{id}        更新知识条目
  DELETE /api/knowledge/{id}        删除知识条目
  GET    /api/documents/{id}/pending_knowledge          文档待审核知识草稿
  POST   /api/documents/{id}/confirm_pending_knowledge  确认草稿入库
  POST   /api/documents/extract_combined_drafts         PRD+脑图合并知识抽取（脑图优先，上传后触发）

  — Skill（测试设计经验）—
  GET    /api/skills                技能列表
  GET    /api/skills/{id}           Skill 详情（含 content）
  POST   /api/skills                新建 Skill（人工）
  PUT    /api/skills/{id}           更新 Skill（content 改变时 version 自增）
  DELETE /api/skills/{id}           删除 Skill
  POST   /api/skills/regenerate     按模块自动归纳 Skill（LLM）

  — System Prompt 版本化（Phase 4.2，项目隔离）—
  GET    /api/prompts                      可管理提示词列表 + 生效概览
  GET    /api/prompts/{key}/default        取原始建议版本（代码默认）
  GET    /api/prompts/{key}/versions       历史版本列表
  POST   /api/prompts/{key}/versions       保存为新版本（activate 可同时设为生效）
  POST   /api/prompts/{key}/versions/{id}/activate  切换生效版本
  POST   /api/prompts/{key}/reset          恢复使用原始建议版本

  — Prompt 改进建议（Phase 4.2 二阶段，仅 generator，只读建议+人工审核）—
  POST   /api/prompts/{key}/suggestions/generate  分析负反馈生成 pending 建议（不激活）
  GET    /api/prompts/{key}/suggestions           建议列表（默认 status=pending）
  POST   /api/prompts/suggestions/{id}/dismiss    忽略建议
  （采用建议无独立端点：走 POST /prompts/{key}/versions，可带 from_suggestion_id 标 adopted）

  — 系统 —
  GET    /health                    健康检查
