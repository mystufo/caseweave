## 1. 5 分钟上手

1. 打开 <http://47.93.126.69:3001/>，用邮箱注册一个账号并登录。
2. 在项目列表里进入一个项目（没有可选项目时找管理员建/公开一个）。
3. 左侧点 **「生成测试用例」** 新建会话。
4. 在引导卡里 **上传需求文档**（`.docx` / `.pdf`），也可以直接贴**飞书文档链接**。
5. 上传解析完成后点 **「开始生成」**，依次走完：
   **确认模块 → 审核知识草稿 → 回答澄清问题 → 生成用例**。
6. 用例出来后在表格里点赞/点踩/就地编辑，然后到 **「用例管理」** 页点 **导出 Excel**。

整条链路里，唯一需要你认真投入的是第 5 步的**澄清问答**——回答得越具体，用例质量越高。

## 2. 注册、登录与项目

### 2.1 账号

- 首页即登录/注册页，**邮箱 + 密码（≥ 6 位）**，昵称可选。
- 登录态保存在浏览器本地，默认有效期 7 天，过期后重新登录即可。
- **管理员**由部署时的 `ADMIN_EMAILS` 配置决定；普通账号注册后即可加入已有项目协作。

### 2.2 项目

登录后先进 **选择项目** 页。项目是数据隔离的单位——会话、用例、知识库、Skill、提示词版本**都按项目隔离**。

| 角色 | 能做什么 |
|------|----------|
| 管理员 | 创建 / 删除项目、切换项目的**公开/私有**、查看全站 token 用量 |
| 普通用户 | 进入公开项目或自己有权限的项目，正常使用全部功能 |

> 删除项目会**连带清除该项目下所有会话与用例**，且不可恢复，谨慎操作。

多人共用同一个项目是被鼓励的：大家的反馈与沉淀的知识会共同喂给同一套进化闭环。

## 3. 界面导览

进入项目后是主工作台，从左到右分三栏：

**最左侧竖条 —— 四个功能页**

| 图标 | 页面 | 用途 |
|------|------|------|
| 💬 | **对话** | 上传文档、澄清、生成用例/脑图 |
| ✅ | **用例管理** | 跨会话聚合所有用例，筛选、编辑、导出 Excel |
| 📖 | **知识库** | 项目沉淀的产品规则/约束/术语，以及模块、Skill、文档 |
| 📈 | **进化报告** | 负反馈归纳记录，看系统「学到了什么」 |

**中间 —— 会话列表**

- 顶部两个按钮：**生成测试用例** / **生成测试脑图**，点一下就建一个新会话。
- 会话可**双击重命名**、可删除（删除会连同该会话的用例与澄清记录一起清掉）。
- 会话之间互相独立，可以同时开着多个、来回切换。

**右侧 —— 对话主区**

顶部常驻**步骤条**，随时告诉你流程走到哪一步：

- 用例模式：`上传资料 → 确认模块 → 审核知识 → 澄清 → 生成用例`
- 脑图模式：`上传需求文档 → 澄清 → 生成脑图 → 存入飞书`

底部是输入框，左侧一排图标分别是：上传 PRD（`.docx`/`.pdf`）、上传测试脑图（`.md`）、粘贴脑图大纲、从飞书链接导入。

## 4. 主流程：生成测试用例

### 第 1 步：上传资料

新建「生成测试用例」会话后，主区会出现 **「第一步：上传资料」** 引导卡，四种入口任选：

| 方式 | 支持格式 | 说明 |
|------|----------|------|
| 上传需求文档 | `.docx` / `.pdf` | 最常用。正文、表格都会被解析 |
| 上传测试脑图 | `.md`（Markdown 大纲） | 已有测试思路时，用它给生成打底 |
| 粘贴脑图大纲 | Markdown 文本 | 从脑图工具里复制出来直接贴 |
| 飞书链接 | 飞书文档 / 知识库链接 | 可一次贴多个链接；需部署侧配好 `lark-cli` |

**PRD 和脑图可以只传其一，也可以两个都传。** 两个都传时系统会合并理解，**冲突以脑图为准**。

上传过程有实时进度（校验 → 抓取 → 解析 → 澄清），解析完成后会出现文件 chip，显示正文字数以及**是否被截断**（单文档正文默认上限 3 万字，超出部分会被截掉并明确提示）。

资料齐了，点 **「开始生成」** 进入下一步。

### 第 2 步：确认模块

系统会判断这份文档属于哪个**模块**（如「订单管理」），并弹出**模块确认卡**让你拍板：

- 命中已有模块 → 直接确认；
- 判断不准 → 从下拉里改选；
- 确实是新领域 → **新建模块**，填：
  - **模块名**（中文，如 `订单管理`）
  - **英文名 / 用例编号前缀**：必须**大写字母开头**，只含 `A–Z`、`0–9` 和短横线，长度 1–40，例如 `ORDER-MGMT`。它决定生成用例的编号前缀。
  - 一句话描述（可选）

模块是知识库、Skill、用例筛选的组织单位，**这一步选对，后面所有沉淀才落在正确的抽屉里**。

### 第 3 步：审核知识草稿

系统会从文档里抽取「可以长期沉淀的产品知识」（规则、约束、术语、UI 行为等）做成**草稿**，交给你审核：

- 勾选要**永久写入项目知识库**的条目；
- 点铅笔可修订内容、改类型、调置信度；
- 完全重复的条目已自动过滤；
- 与库内已有内容**相似**或**冲突**的条目会单独列出对照与判定理由，需要你逐条选择
  **「保留新的（替换旧条目）／保留旧条目／两个都保留」**（默认两个都保留）；
- 也可以整批 **全部入库** 或 **全部丢弃**。

审核完的知识会在后续所有生成里被检索并注入 —— 这是系统越用越准的主要来源之一。

> 想省事可以先全部入库，之后随时在「知识库」页增删改。

### 第 4 步：澄清

这是最关键的一步。Clarifier Agent 会结合知识库读文档，把**歧义、缺失、边界不明**的地方列成问题，例如「超时时间没写，按多少秒算超时？」。

- **逐题作答**，答案会直接进入生成上下文；
- 提交后大模型判断是否还需要继续追问，**最多 5 轮**；
- 确实没疑点时会直接放行到生成；
- 实在答不上来的问题可以写「按默认/待定」，但**含糊的回答会换来含糊的用例**。

最后一轮的按钮会变成 **「提交回答并生成测试用例」**，点它直接进生成。

### 第 5 步：生成用例

生成过程是流式的，中途可以**停止**。产出是一张结构化表格，字段包括：

`用例编号 / 用例名称 / 用例模块 / 优先级 / 前置条件 / 执行步骤 / 预期结果 / 备注`

表格里可以直接：

- ✏️ **就地编辑**任意字段（编辑会被记录为反馈，喂给进化闭环）
- 👍 **赞** / 👎 **踩**（踩可以补一句原因，如「漏了边界」「步骤太粗」）
- 🗑️ 删除单条（二次确认）

## 5. 另一条流程：生成测试脑图

如果你想要的不是 Excel 用例，而是一张**测试思路脑图**，新建会话时选 **「生成测试脑图」**。

流程更短：`上传需求文档 → 澄清 → 生成脑图 → 存入飞书`

- 只需上传 PRD（本地文件或飞书链接）；
- 同样先走澄清（最多 5 轮），最后一轮按钮是「提交回答并生成测试脑图」；
- 生成完成后**直接写入飞书**，卡片上给出可点击的文档链接，可以「重新生成」。

典型用法：**先跑脑图对齐测试思路 → 人工调整脑图 → 再开一个用例会话，把脑图连同 PRD 一起传进去生成用例。**

## 6. 用例管理与导出 Excel

「用例管理」页是**跨会话的聚合视图**，把项目里所有会话生成的用例按模块归拢在一起。

- **筛选**：按模块、优先级、创建时间；
- **就地编辑**：双击单元格改内容，改完即存；
- **删除**：单条删除，二次确认；
- **列宽**：拖表头右边缘可调，浏览器会记住；
- **点赞/点踩**：和对话里的表格一样，同样驱动进化。

点右上角 **「导出 Excel」**，下载的是**当前筛选结果**。Excel 特点：

- **按模块分 Sheet**，没有模块的归到「其他」；
- 表头冻结，列宽已调好；
- 表头字段与页面一致，另附一列 **自测结果** 供执行时填写。

## 7. 知识库（待优化）

「知识库」页管理项目长期沉淀下来的东西：

- **知识条目** —— 产品规则、约束、术语、UI 行为等，带类型、置信度、所属模块。可搜索、按模块筛选、编辑、删除，也可以把「项目级（无模块）」的条目**归类到某个模块**。
- **模块** —— 增删改，以及维护**模块间关联关系**（比如「订单」依赖「支付」），关联会影响知识检索范围。
- **Skill** —— 每个模块的可复用测试设计经验（由系统从你的编辑/负反馈里蒸馏，也可以手动写/一键重新生成），生成用例时注入。
- **需求文档 / 脑图** —— 该模块下已积累的原始资料。

这些内容在每次澄清和生成时都会被**语义检索**出最相关的若干条注入提示词，所以：**知识库越干净，生成越贴合你们的产品。** 发现有错的条目直接删掉，比什么都有效。

## 8. 反馈与自我进化（待优化）

系统的进化燃料只有三种，都来自你的日常操作：

| 你的动作 | 系统怎么用 |
|----------|-----------|
| 👍 赞 | 正样本，强化当前生成风格 |
| 👎 踩（+原因） | 归纳意图，分诊到具体出口去改 |
| ✏️ 编辑用例 | 对比编辑前后的差异，反推「哪里生成得不对」 |

负反馈会被归一成意图（如「补充边界用例」「修正业务规则」「操作步骤太粗」），再分诊到**三个出口**：

- **系统提示词** —— 生成 Prompt 改进建议（草稿，需人工采纳）
- **Skill** —— 蒸馏成该模块的测试设计规则
- **知识库** —— 沉淀成产品规则/约束

**「进化报告」页**就是这套闭环的账本：能看到每条负反馈的点踩原因、改动字段、关联用例、意图分布、**流向了哪个出口**、以及**是否已被该出口消费**（「待消化 / 已消化」）。

> 一句话：**点踩时顺手写一句原因**，是你能给这个系统提供的性价比最高的输入。

## 9. 提示词管理

对话页可以打开 **系统提示词管理** 抽屉，管理三个 System Prompt（**按项目隔离**）：

- `clarifier_initial` —— 首轮澄清
- `clarifier_followup` —— 追问
- `generator` —— 用例生成

能做的事：

- 查看**默认版本**（代码内置的「原始建议版本」）与全部**历史版本**；
- 编辑并保存为**新版本**，一键**切换生效**，随时**回滚**或**重置为默认**；
- 查看系统基于负反馈自动生成的**改进建议草稿**（`generator`），逐条**采纳**（采纳即生成新版本）或**忽略**。

> 建议：**系统生成的建议永远只是草稿，不会自动生效**，采纳前先读一遍改动理由。改坏了随时切回上一个版本。

## 10. 使用限制与配额

以下参数可以在.env里进行动态设置：

| 限制 | 表现 | 配置项（默认值） |
|------|------|------------------|
| **单账号并发** | 同一账号同时只能跑 1 个 LLM 任务，重复提交会被直接拒绝 —— 等上一个跑完再点 | `LLM_MAX_CONCURRENCY_PER_USER`（1） |
| **全局并发** | 全站同时最多 3 个任务，超出的会**排队**，界面显示「排队中」，轮到你会自动继续 | `LLM_MAX_CONCURRENCY`（3）、`LLM_QUEUE_SIZE`（20）、`LLM_QUEUE_TIMEOUT_SECONDS`（180） |
| **每日 token 配额** | 按自然日计算，超额当天不能再发起生成 | `DAILY_TOKEN_QUOTA`（0 = 不限）、`QUOTA_RESET_UTC_OFFSET_HOURS`（8，即东八区跨日）、`QUOTA_EXEMPT_ADMINS`（true，管理员豁免） |

其他实际会碰到的边界：

- 单文档正文上限 **3 万字**（`DOC_MAX_CHARS`），超出会截断并在界面明示；
- 澄清最多 **5 轮**（代码常量 `MAX_CLARIFICATION_ROUNDS`，不走 `.env`）；
- 单次 LLM 调用有超时限制（`LLM_TIMEOUT_SECONDS`，默认 120 秒），超大文档建议**按模块拆分**上传。

> 管理员可用 `GET /api/limits/usage?granularity=day|week|month&periods=N`（最多 31 组）查看各账号按天/周/月的 token 消耗，前端对应「Token 用量」页；任何用户都能用 `GET /api/limits/status` 查自己的余量。

## 11. 常见问题

**Q：上传文档报「Only .docx and .pdf files are supported」**
需求文档只接受 `.docx` 和 `.pdf`。`.doc` 请先另存为 `.docx`；测试脑图只接受 `.md`（Markdown 大纲）。

**Q：扫描件 PDF 传上去几乎解析不出内容**
PDF 走文本抽取，纯图片扫描件抽不到文字。请用可选中文字的 PDF，或改传 Word。

**Q：飞书链接导入失败 / 一直卡在「校验飞书链接」**
飞书导入依赖服务端的 `lark-cli` 与授权身份，需要部署侧配置。失败时界面会给「重试」按钮；持续失败请联系管理员，或先把飞书文档导出成 Word 再上传。

**Q：为什么一定要先答澄清问题？能不能跳过？**
澄清是质量的来源。若文档本身足够明确，系统会判定「无遗留疑点」直接放行；否则**建议老老实实答完**——跳过换来的是一堆需要返工的用例。

**Q：生成的用例编号前缀不对**
前缀由**模块的英文名**决定，去「知识库 → 模块」里改，或在下次的模块确认卡上改选/新建正确的模块。

**Q：页面提示「排队中」或直接被拒**
见 [第 10 节](#10-使用限制与配额)。稍等片刻重试即可，不要连点。

**Q：中途网络断了 / 刷新了页面，之前的进度还在吗？**
在。会话、文档、澄清记录、已生成用例都存在服务端，刷新后回到该会话可继续；正在跑的流式任务若被中断，按界面提示重试即可。

**Q：数据是隔离的吗？**
按**项目**隔离。同一项目内的成员共享会话、用例与知识库。公网这台是**公开体验环境**，请**不要上传涉密或含敏感客户信息的文档**。

## 12. 用得更好的几条经验

1. **一次只喂一个模块的需求。** 一份大而全的 PRD 拆成几次跑，模块归类更准、用例粒度更稳。
2. **澄清答案写具体值。** 「超时 30 秒，超时后重试 2 次」远胜「按常规处理」。
3. **点踩一定写原因。** 一句「漏了并发场景」就能沉淀成这个模块以后一直生效的 Skill。
4. **编辑而不是重生成。** 直接在表格里改，系统能学到「差在哪」；整批重生成学不到东西。
5. **定期打扫知识库。** 过时的产品规则留在库里，会持续污染后面的生成。
6. **PRD + 脑图一起传。** 有历史测试思路时，这是提升用例覆盖度最快的方式。
